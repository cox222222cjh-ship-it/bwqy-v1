# item-query-v1 收口说明

## 结论

当前仓库可以按 v1 定位收口：主线能力仍然保持“本地只读、最小闭环、可信优先”，且本次核验未发现应阻止收口的 blocker。

## v1 已交付范围

- 仅支持物品名称 / 物品 ID 查询。
- 查询可信锚点仅为 `ItemTable` 主表记录。
- 展示范围限定为：基础信息、分类、来源信息、可信状态、装备链路。
- 装备链路仅覆盖 v1 最小集合：`ItemTable`、`ItemSetTable`、`ItemSetAbilityTable`。
- 所有展示项都要求带来源表、来源字段与状态（`direct` / `derived` / `pending_confirmation`）。
- 无法充分确认的字段必须显式展示为“待确认”，不能伪装成确定事实。

## 当前数据范围

本地核验时实际装载的数据表仅包含以下三张：

- `ItemTable`：25163 行。
- `ItemSetTable`：350 行。
- `ItemSetAbilityTable`：838 行。

说明：v1 当前只针对上述三张表构建本地只读索引，不扩展到任务、礼包、强化、产出或更强搜索链路。

## 已验证内容

- OpenSpec `build-v1-item-query-tool` 的 proposal / design / tasks / spec 与 README 已复核，当前实现边界仍与 v1 范围一致。
- 自动化测试全部通过，覆盖查询入口、结果页模型、Web UI、最小验收样例。
- 本地 smoke 已验证 Web UI 可启动，并可对真实数据执行一次最小查询请求。
- 代码核查确认：
  - 未发现将不确定项伪装为确定值的输出；
  - `pending_confirmation` 在详情页与候选结果中保持可见；
  - 装备链路未超出套装最小链路范围；
  - 当前仓库内未发现明显乱码残留；
  - README 的主线说明与实现总体一致。

## 已知限制

以下问题不构成当前 v1 收口 blocker，但应明确记录为已知限制：

- 名称查询仍为精确匹配，不提供模糊搜索、分词搜索或更强召回。
- 若底层数据存在重复 `TID`，当前索引以最后一条记录覆盖，未做显式告警。
- 装备判定仍是保守推断规则（`SetTID > 0` 或 `AP/DP/BP/CP` 任一非 0），因此“是否装备”不是官方分类事实。
- 装备链路仅覆盖套装链路；非套装装备的强化、分解、炼金、合成等链路不在 v1 范围。
- 中文分类名仍保持“待确认”，因为当前没有可验证的官方编码字典。
- 仓库运行依赖上层目录中的本地 `data/tables` 数据；若缺少该数据目录，页面会进入启动错误态而不是提供伪造结果。

## 后续变更边界

- v1 到此为止，不继续堆功能。
- 任何后续增强（例如更强搜索、更多关联表、显式重复主键告警、装备分类字典、更多前端交互）都应新开 change，不能继续并入当前 v1 收口。

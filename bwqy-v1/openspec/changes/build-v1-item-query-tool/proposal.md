# Change Proposal: build-v1-item-query-tool

## Summary

构建一个本地只读的网页查询工具，面向运营使用。第一版只解决“物品查询”这一件事：支持通过物品名称或物品 ID 命中物品主表记录，并返回可信、可追溯的基础信息与最关键的装备链路。

本次变更以“结果可信优先于覆盖完整”为最高原则，不追求全业务域统一入口，也不追求一次性打通全部关联表。

## Why

当前项目方向已经明确：这是一个绿地项目，第一阶段目标不是做全功能配置百科，而是先做一个运营能用、查得准、说得清的本地查询工具。

如果把任务、礼包、强化、复杂相关表定位一起放进第一版，会明显扩大范围，增加不确定性，降低第一版交付成功率。因此本次变更明确压缩范围，只保留最小可用闭环。

## Goals

本次变更必须实现以下目标：

1. 用户可以通过物品名称或物品 ID 查询物品。
2. 查询结果以物品主表为可信锚点。
3. 结果页展示物品的基础信息。
4. 如果该物品属于装备，展示最关键的装备链路信息。
5. 每个结果项都必须能说明来源表、来源字段，以及是直接读取还是推断。
6. 无法充分确认的结果必须显式标记为“待确认”。

## Non-Goals

本次变更明确不包括以下内容：

- 任务查询
- 礼包查询
- 强化链路完整实现
- 全量“相关表出现位置”展开
- 多业务域统一入口
- 正式联网服务
- 写操作
- 权限系统
- 大规模复杂前端交互

## Success Criteria

本次变更完成后，应满足以下标准：

1. 运营可以在本地网页中输入物品名称或物品 ID，并拿到结果。
2. 对于命中物品，页面能稳定展示基础信息。
3. 对于装备类物品，页面能展示最关键的装备链路。
4. 页面上的每个展示项都能说明来源。
5. 错误或不确定信息不会伪装成确定结果。

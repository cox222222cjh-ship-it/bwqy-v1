# Design: build-v1-item-query-tool

## Overview

本次变更采用“主表优先、可信优先、局部关联”的设计策略。

系统先围绕物品主表构建查询入口和结果展示，再补装备链路这一条高价值关联。第一版不追求统一抽象全部业务域，而是先把“物品查得准、结果讲得清楚”做出来。

## Data Strategy

第一版的数据策略如下：

1. 只读取本地 CSV 数据。
2. 建立面向物品主表的查询索引。
3. 分类判断优先基于主表直接字段或确定性最高的映射。
4. 装备链路只接入一小组确定性最高的关联表。
5. 任何跨表扩展都必须带可追溯信息。

## UI Strategy

页面只保留两块核心区域：

1. 查询输入区  
   仅支持物品名称和物品 ID 输入。

2. 结果展示区  
   展示基础信息、分类、来源、装备链路。  
   不做复杂筛选器、不做多页签大布局、不做“百科式”超长详情。

## Trust Model

系统中的每个结果项都归类为以下三种之一：

- 直接读取
- 推断
- 待确认

页面必须对用户可见这三种状态，而不是只在后台保留。这样可以保证第一版即使覆盖不完整，也不会误导用户。

## Risks

主要风险有四个：

1. 物品分类字段不足，导致分类识别不稳定。
2. 装备链路涉及多个表时，容易出现“能连上但不够可信”的情况。
3. 如果一开始把关联表范围做大，v1 会失控。
4. 页面展示需求容易膨胀成“全功能详情工具”。

## Risk Mitigations

对应措施：

1. 先只做高确定性的分类规则。
2. 装备链路只纳入最关键的一条。
3. 以主表结果页为主，不做全量相关表总览。
4. 每个新增展示项必须先回答“来源是什么、可信度是什么”。

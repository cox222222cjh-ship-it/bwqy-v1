# Task 1 - MVP Scope Freeze（v1 范围冻结）

## 1) 冻结目标

本文件用于冻结 `build-v1-item-query-tool` 的 v1 最小闭环范围，作为后续实现与评审基线。

冻结原则：

1. 结果可信优先于覆盖完整。
2. 物品主表优先于跨表扩展。
3. 每个展示项必须可追溯（来源表 / 字段 / 状态）。
4. 不确定内容必须显式标记为“待确认”。

## 2) v1 In-Scope（必须实现）

### 2.1 查询入口

- 仅支持“物品查询”。
- 支持两种输入：
  - 物品名称（`LocalName`）
  - 物品 ID（`TID`）
- 查询命中优先基于物品主表（`ItemTable.csv`）。

### 2.2 结果展示（最小字段集）

- 物品基础信息（至少包含 `TID`、`LocalName`、`EngName`、`Level`、`Grade`）。
- 物品分类信息（先展示可直接读取的分类编码字段，如 `Type`、`Kind`、`Property`）。
- 来源信息（来源表、来源字段）。
- 可信度状态（直接读取 / 推断 / 待确认）。
- 装备链路（仅保留一条高确定性链路，见 Task 2）。

### 2.3 数据与运行边界

- 仅处理本地 CSV。
- 仅只读，不做写操作。
- 不引入联网依赖。

## 3) v1 Out-of-Scope（明确不做）

以下内容下沉到后续版本，不得在 v1 实现中夹带：

1. 任务查询。
2. 礼包查询。
3. 强化链路完整实现（仅保留最关键装备链路，不做全链路）。
4. 全量“相关表出现位置”展开。
5. 多业务域统一入口。
6. 正式联网服务。
7. 写操作。
8. 权限系统。
9. 复杂前端交互（多页签、复杂筛选、百科式长详情）。

## 4) 范围闸门（Scope Gates）

后续新增字段/功能必须同时满足以下条件，否则不进入 v1：

1. 能回答“来源表/字段是什么”。
2. 能回答“是直接读取还是推断”。
3. 若证据不足，能明确标注“待确认”。
4. 不扩大到非物品域（任务/礼包等）。

## 5) 与 Task 2 的接口约束

Task 2 需要在本冻结范围下输出：

- 主表与最小关联表清单。
- 搜索字段、分类字段、装备链路字段清单。
- 字段状态分级（直接读取 / 推断 / 待确认）。

在 Task 2 未稳定前，不进入 UI 复杂交互与多链路扩展。
